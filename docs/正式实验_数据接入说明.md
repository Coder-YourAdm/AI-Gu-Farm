## 一、一句话结论

B 的正式实验结果**已全部接入展示**，四条页面要求全部落实；但接法是**新增一层独立页面**
`web/formal.html`，**不是覆盖 `web/result.json`**。原因在第二节，这是硬约束不是偏好。

## 二、为什么不能直接把 brief 写进 web/result.json

上一轮（新项目线）已经实测过替换后果，本分支又逐条核了一遍：

| 项 | `web/result.json`（现有交付） | `result_brief.json`（B 的正式实验） |
|---|---|---|
| schema | `result-board` v1 | `result_brief/1` |
| 数据 | `E_real_20261114_r1` 等 **3 趟重测** | `E_s42/F_s42/E_s43/F_s43/E_s44/F_s44` **6 趟** |
| 核心字段 | `runs[].lineages[].holdout`（逐题留出） | `pairs[].final` / `checkpoints` / `challenges` / `limits` |
| 生产者 | `app/evaluate.py`（`generated_by` 被测试钉死） | `tools/build_result_brief.py`（B 本机，未入库） |
| 证据 | `runs/*.jsonl` 逐条可复算，已进 `证据包/` | 只有汇总简报；**原始逐题记录与代码版本未入库** |

直接替换会同时踩三个雷：

1. **`tests/test_result.py::test_on_disk_json_is_consistent_with_its_producer` 变红**
   —— 它断言 `generated_by ∈ {tests/make_fake_result.py, app/evaluate.py}`，
   且真数据分支要校验 `provenance.runs_count == len(runs)`、`calls_total == sum(calls)`。
2. **`web/result.html` 白屏** —— 页面按 `result-board` 的 `lineages / holdout / metric` 渲染，
   brief 里这些键一个都没有（上一轮实测 `TypeError: string indices must be integers`）。
3. **数据哨兵与证据包失效** —— `tools/check_web_data.py` 要求 `run_prefix = E_real_20261114_`；
   `证据包/01_数字对照表.md` 的全部数字都从 `runs/*.jsonl` 重算，换数据后整包变成假账。

更根本的一条：**brief 没有逐题留出明细**，物理上凑不出 `result-board` 的 `holdout.correct/total`，
所以「写个转换器把它转成 result-board」也是伪解法——会造出一批编造的逐题数字。
按项目铁律（不许改现有测试断言、不许页面写死数字），只能新增一层。

## 三、接法：新增一层，不动任何现有交付文件

```
docs/result_brief.json ── tools/build_formal_page.py ──> web/formal.html（内联数据，断网可开）
docs/B_交付简报.md   ─┐
docs/B_运行清单.md   ─┼── 原件入库，供人读与溯源
docs/给C_交付说明_20261114.docx / .md ─┘
web/{index,evolve,result}.html ── 各加一个「正式实验」互跳入口（只加一行 <a>，其余不动）
```

- `web/result.json` / `web/data.js` / `history.json` / `evolve.json` **一个字节没改**
- `tests/`、`app/`、`data/` **一行没碰**
- 页面所有数字从内联 BRIEF 读取，页面内不写死数值；换 brief 重跑生成器即可
- 点页面任意数字，会浮出它在 `result_brief.json` 里的字段路径

## 四、B 的「页面接入四个要点」逐条落实

| B 的要求 | 落实位置 | 核对方式 |
|---|---|---|
| `web/result.json` 换真数据、`is_mock=false`、去掉 mock 徽章 | 现有 `result.json` **本来就是** `is_mock:false / backend:real`，`result.html:315` 挂的是绿色「真模型」标；新页 `formal.html` 同样挂真模型绿标 | `python tools/check_formal_page.py` 第 ① 条 |
| 挑战图用 `runs[].stats.challenges`，X04 六个 0、X05 最高 2，`window_closed` 不要画成达标 | `formal.html` 逐次观察格子：四趟 × 六次，标「观察窗口已关闭 · 六次内未达 3/6 门槛，不画成达标」 | 同上第 ② 条 |
| `E_s44` 取消、`F_s44` 未启动，按「取消/未启动」展示，不能显示成 0 分 | 运行状态卡：E_s44「第 7 代取消（`operator_cancelled`）」、F_s44「未启动（`operator_cancelled_before_start`）」，均写「不参与配对，不计 0 分」，且不带任何分数 | 同上第 ③ 条 |
| `limits[]` 五条必须上页面 | `formal.html` 独立「限制 · 必须与结果一起出现」区块，逐条渲染 `BRIEF.limits` | 同上第 ④ 条 |

**一处按数据纠偏**：B 文档写「X05 最高 2（E_s43 第 4 次）」，机读数据里 `2` 出现在
**F_s42 与 E_s43 两趟**的 `gen 19`（六次观察中的第 5 次），且数据里的 `state` 是
`retired`（完成趟）/ `censored`（取消趟），不是文档写的 `window_closed`。
页面按机读数据画，状态翻译成中文并保留原始英文值，避免评委误读成「达标」。

## 六、回 B 的三个问题（docx §8）

1. **`result_brief.json` 字段够不够接页面？** 够。主结果、曲线、分题型、挑战观察、
   题族分布、六趟状态、五条限制、协议参数全部字段化，页面没缺字段，也没写死常量。
   唯一欠的不是字段，是**原始证据与代码版本入库**（见第五节）。
2. **mock 徽章什么时候能去掉？** 在本分支早就去掉了：`result.json` 是
   `is_mock:false`，`result.html` 挂绿标；新页 `formal.html` 也是绿标、无 mock 字样。
   B 看到的 mock 徽章来自**新项目 main** 上的 `r1113E01` 假数据——那是另一个仓库状态的联调数据，
   不是本交付线。
3. **要不要 X04/X05 逐次观察 CSV？** 不用另出 CSV，`result_brief.json` 里已有四趟 × 六次
   的 `observations`，页面直接读它画格子，少一份文件就少一处口径分歧。
   若展板要单独素材，可从 `docs/result_brief.json` 现场导出，不必预先再维护一份。
