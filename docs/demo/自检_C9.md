## 八、C8 真实 HTTP 自检（15:45 补做，不等 B）

**动机**：C7 预案是「接口没好先用假响应占位」，所以 `LIVE.endpoint=null`，
实时走页面内置假 Tutor。这导致 C8 的验收动作「关掉后端再点」**没有真后端可关**——
原 `check_live.js` I 段只是把 `global.fetch` 换成 `Promise.reject(new Error("ECONNREFUSED"))`，
那是写死的假错误，证明不了真实网络故障下页面还能切回回放。

**做法**：新增 `docs/demo/check_live_http.js`（Node >= 18，零 npm 包、零外网）：

1. 在 `127.0.0.1` 随机端口起一个真 HTTP 服务，`POST /api/ask` 返回**契约 4.5 的完整形状**
   （`ok / turn / kc / verdict / err / statement / answer_format / hint / mastery / why / review / elapsed_ms`）；
   判分走服务端有理数比较，六道题与页面 `LIVE_POOL` 同口径。
2. 运行时把 `LIVE.endpoint` 注入为本地 URL（**只在内存里注入**，源码 `web/tutor.html` 保持 `endpoint: null`）。
3. 服务在：`setMode("live")` 真实发出 `action=start`、连答 5 题全走网络、判 right/wrong、提示级别递增、reset 回首题。
4. `server.close()` **真的关掉服务**后再点：连接被拒 → 页面提示「实时模式不可用（fetch failed）」、
   `LIVE.on=false` 自动切回放、回放题面仍在渲染不白屏。
5. 重启服务：能重新进入实时；让后端返回 `{"ok":false,"error":"Tutor: mock 后端故障"}`，同样回退且提示带出错误原文。

**结果**：21 项全 PASS，已接入 `docs/demo/check_all.ps1` 作为第四套自检。
意义有两层：① C8 的失败路径从「桩模拟」升级为「真实网络故障」；
② 顺带验证了「B 的接口一到位，只改 `LIVE.endpoint` 一处」这句话是真的——
mock 服务返回的就是契约形状，页面渲染路径一行没改。

**边界**：脚本仍用轻量 DOM 桩加载页面脚本（沙箱起不了浏览器），
所以只证明「脚本层 + 网络层」不塌，**不等于真人浏览器验收通过**；
C8/C9/C13 的完整真人路径仍需非沙箱机器，见第五节。
