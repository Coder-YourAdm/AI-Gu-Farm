# C13 布局自检（1280 / 1920）

> 目标：答辩投影上**不溢出、不遮挡、不糊**。
> 脚本：`docs/demo/check_layout.js`（贴进浏览器控制台，不依赖任何库）

## 一、怎么测（每页 2 次，共 6 次，约 4 分钟）

1. 双击打开 `web/cover.html`（或 `tutor.html` / `compare.html`）。
2. `F11` 全屏，`Ctrl+0` 把缩放重置到 100%。
3. 按 `F12` 打开控制台 → 把 `check_layout.js` 的全部内容粘进去 → 回车。
4. 第一行会是 `[C13] PASS` 或 `[C13] FAIL`：
   - PASS：记录一行「PASS」。
   - FAIL：`console.warn` 会逐条列出**具体元素和像素**，照它修。
5. 用 DevTools 的响应式模式（`Ctrl+Shift+M`）把视口改成 **1280×720**，重跑一次；再改 **1920×1080**，重跑一次。

## 二、通过标准

| 页面 | 1280×720 | 1920×1080 | 附加硬数字 |
|---|---|---|---|
| `cover.html` | 无横向溢出、整页不滚 | 同左 | 数字卡片 3 张 |
| `tutor.html` | 无横向溢出、整页不滚 | 同左 | 掌握度 3 条、对话流宽度 ≥ 360px |
| `compare.html` | 无横向溢出、整页不滚 | 同左 | 明细 9 行、条形组 3 组 |

六格全 PASS 才算 C13 过。**整页纵向溢出**是重点：三页都改成了 flex 竖排（C6），面板内部滚动、页面本身不该出现滚动条——如果这里报错，先 `Ctrl+F5` 清缓存，再检查是不是又有人加回了 `calc(100vh - ...)`。

## 四、常见 FAIL 与处理

| 报错 | 多半原因 | 怎么修 |
|---|---|---|
| 页面横向溢出 | 某个固定宽度 > 视口，或长英文/公式不换行 | 找到 warn 里的元素，加 `min-width:0` 或 `overflow-wrap:anywhere` |
| 整页纵向溢出（tutor） | 提示条出现 + 又用回了 `calc(100vh - 57px)` | 确认 `body` 是 `display:flex;flex-direction:column`、`main` 是 `flex:1` |
| 整页纵向溢出（cover） | 720 高度下 hero + 三个数字 + CTA 加起来超了 | 缩 `h2.hero` 的 clamp 下限或 `.nums` 的 `margin-top` |
| 元素越界（`#turns` 等） | 三栏 grid 在 1280 下挤压 | 检查 `main` 的列宽，必要时把右栏 330px 降到 300px |
| 字号过小 | 有 `font-size:9px` 这类标注 | 抬到 ≥ 10px（投影上 9px 基本看不见） |
| 提示条可见 | `web/tutor.json` 没到位 | 不是 bug；但**正式截图前必须补数据**（见操作单第 0 节） |

## 五、真实浏览器验收（2026-11-14 17:0x，补上原「只能换机器」的缺口）

**先纠正一个旧判断**：`自检_C9.md` 与 `自检_逐项对照_C0-C13.md` 早先写「本机沙箱起不了浏览器，
C13 只能换非沙箱机器」——**不准确**。`--headless --screenshot` 与 `--dump-dom` 确实不落盘/输出空，
但 **CDP 通道可用**：`chrome --headless=new --remote-debugging-port=<port>` 能起，
`Page.captureScreenshot` 通过 WebSocket 把 base64 回传内存，能截图、能取真实布局、能派发真实鼠标事件。

**复跑命令**（自带临时静态服务、零 npm 包、零外网）：

```bash
node docs/demo/check_browser.js            # 只验，已接入 check_all.ps1 第五套
node docs/demo/check_browser.js --shots    # 额外写 7 张截图到 docs/demo/shots/
```

**实测结果**：三页 × 1280/1920 六格全 PASS（横纵均不溢出、越界元素 0、`reference` 0、黄条 0、
JS 异常 / console.error / 4xx 均 0）；C2 三处交互用 `Input.dispatchMouseEvent` 发真实鼠标点击全通过；
C9 整条路径 cover→tutor→compare 无白屏；C6 封面点「诊断页」真实跳转成功。
截图 7 张：`cover/tutor/compare × 1280/1920` 六张 + `tutor_why_1280.png`（点题面后理由面板展开）。
CDP 截图只有页面内容，**天然无地址栏**；页面真数据到位，无 mock 徽章。

**顺带修掉一个真 404**：首次导航时 Chrome 会在解析 HTML 前隐式请求 `/favicon.ico`，
控制台报 404，让「无 404」有解释成本。三页 `<head>` 加 `<link rel="icon" href="data:,">`（零外链），
并补 70 字节的 `web/favicon.ico` 兜住首次隐式请求；复跑六格错误数归 0。

**边界（别把 CDP 说成真人验收）**：这是真实 Chrome 渲染 + 真实鼠标事件，比 DOM 桩强得多，
但**不等于人眼看投影可读性**，也不等于 C12 彩排计时。这两项仍需人在现场走一遍。
`check_layout.js` 是浏览器 DevTools 内脚本（读 `window.innerWidth`），不能当 Node CLI 跑。
