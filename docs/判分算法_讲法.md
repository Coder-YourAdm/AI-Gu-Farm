# 判分算法 · 讲法（对着真实代码讲，不凭印象）

> **用途**：答辩被问「你们凭什么说判分可信」时的完整口径。
> 题源见 [`docs/答辩_12问.md`](答辩_12问.md) 第 1 / 5 / 7 问；
> 权威实现是 [`app/executor.py`](../app/executor.py)（契约 `方案/技术规格_v5.md` §2.3 v5.1），
> 单测 `tests/test_executor.py` 49 条全绿。
>
> 本文所有实测结果都是在本仓库真跑出来的，不是示意。

---

## 1. 一句话总纲

> **判分不是一个「打分函数」，是一条双输入流水线：
> 左边由本地精确算术算出参考答案，右边模型只交一个字符串，
> 两边都化成 `Fraction` 才碰面比一次。全程零浮点、零次让模型当裁判，
> 参考解压根不给模型看。**

---

## 2. 四条铁律（写在 `app/executor.py` 文件头）

1. **入口先拒绝，再计算**
2. **全程 `fractions.Fraction`，禁止 `float`**
3. **参考答案只能由本模块算出，不信任何模型输出**
4. **`solver_view()` 是白名单**——给模型的只有 `{type, statement, answer_format}`，
   `reference` / `params` / `template` / `signature` / 历史答题一个都不给

这四条不是代码风格，是把「谁有权判定对错」从模型手里收回来。

---

## 3. 主链路

```
[题目参数]                              [模型输出 raw_answer]
 validate_task（键集合/范围/bool 防御）      六道入口闸
      ↓                                        ↓
 solve_exact() 精确算 reference         integer → fraction → decimal
      ↓                                        ↓
 reference → Fraction                   answer → Fraction
      └──────────────┬─────────────────────────┘
                     ↓
        judge()：只做一次比较 → right / wrong / unanswered
```

`judge()` 是**纯函数**：不读文件、不读配置里的场景标签、不知道这道题是互答还是共同卷。

---

## 4. 参考解怎么算：`solve_exact()` 四个模板

题目只有四类，全是**能精确算、不产生无理数**的题型：

| 模板 | 题面 | 精确解 |
|---|---|---|
| `poly` | ∫ₗᵘ 多项式 dx | `Σ aᵢ(u^(i+1) − l^(i+1))/(i+1)` |
| `gamma` | ∫₀^∞ c·xⁿ·e^(−rate·x) dx | `c·n! / rate^(n+1)` |
| `gaussian_odd` | ∫₀^∞ c·x^(2k+1)·e^(−rate·x²) dx | `c·k! / (2·rate^(k+1))` |
| `det` | n 阶行列式 | **Bareiss 整数消元** |

`bareiss()` 值得单说：整数矩阵用
`(a[i][j]*a[k][k] − a[i][k]*a[k][j]) // prev` 消元，
**全程整数、必然除尽**，主元为 0 就换行翻符号。
所以行列式连分数都不会出现，更不需要浮点。
实测 `[[1,2],[3,4]] = −2`，含零主元 `[[0,1],[3,4]] = −3`。

算出来的 `reference` **用字符串存**：
`{"kind":"integer","value":"9"}` 或
`{"kind":"rational","numerator":"3","denominator":"2"}`——
因为 JSON 里的裸大整数会被解析成 float 丢精度。这道防线很细，少了它前面全白做。

> 题面也由执行器确定性生成（`statement()`，纯函数，同输入同输出），
> 不出现模板名、`rate/c/n` 等变量名，也不写「用阶乘公式」。

## 5. 答案通道：六道闸 + 三级互斥解析

`judge()` 先把输入过六道闸，任何一条不过直接 `unanswered`：

| # | 闸 | 挡什么 |
|---|---|---|
| 1 | 必须是 `str` | `None` / 非字符串 |
| 2 | 长度 ≤ **8000** | **在 `json.loads` 之前就拒**，防超长 DoS |
| 3 | 必须是合法 JSON | 自然语言「答案是 9」 |
| 4 | 键集合**恰为** `{"value"}` | 多一个 `extra` 键也拒 |
| 5 | `value` 必须是 `str` | `{"value": 1}` 数字型 |
| 6 | strip 后非空、≤ **100** 字 | 空串、超长答案 |

过了闸才解析，而且**三级互斥、顺序固定**：
`parse_integer` → `parse_fraction` → `parse_decimal`，每条都要 `fullmatch`。
所有词法检查（**64 位**上限、**指数 ≤30**、分母 ≠0）放在
`int` / `Fraction` / `Decimal` 转换**之前**——
否则一个 `1e999999` 就能喂出天文数字大整数。

**行列式题更严：只接整数**，`-4/2`、`-2.0` 都算 `unanswered`
（`tests/test_executor.py::test_det_accepts_integer_only` 明确锁住）。

## 6. 三态边界实测（∫₀¹(x+1)dx = 3/2，容差 1.5e-8）

| 学生输入 | 内核怎么读 | 判定 |
|---|---|---|
| `{"value":"3/2"}` | fraction 分支，精确相等 | `right` |
| `{"value":"6/4"}` | `Fraction` 自动约分成 3/2 | `right` |
| `{"value":"1.5"}` | decimal 分支，差为 0 | `right` |
| `{"value":"1.50000001"}` | 差 1e-8 ≤ 1.5e-8，容差内 | `right` |
| `{"value":"1.5000001"}` | 差 1e-7 > 1.5e-8，超容差 | `wrong` |
| `{"value":"3/2.0"}` | 三种格式都不 fullmatch | `unanswered` |
| `{"value":"NaN"}` | 不是有限十进制 | `unanswered` |
| `{"value":"1e31"}` | 指数 31 超过上限 30 | `unanswered` |

**为什么单列 `unanswered`**：`wrong` 和 `unanswered` **都计 0 且占分母**。
否则模型发现答不出就故意交个乱码，把这道题从分母里抹掉，正确率虚高。
评委问「为什么三态不是两态」，答这个。

## 7. 四个最容易讲错的口径陷阱（答辩前必记）

**① 容差不是「所有答案都放宽 1e-8」**
`judge()` 注释写「1e-8 相对容差」，代码实际是 `1e-8 × max(1, |ref|)`——
有 1e-8 的绝对下限，再随参考值放大（ref=3/2 时是 1.5e-8）。
而且**只有答案走 decimal 分支才启用**。整数、`a/b` 分数、行列式一律严格 `==`。
正确说法：**「除了手写小数，全都是精确相等」**。

**② 「判分 0 浮点」只指判分内核，不是全仓库**
`app/scoring.py::scores()` 算演化适应度时是**有 float** 的：
`set_score = min(c, 5-c)/2`、`bounty = 2.0`、
`total = solve + set_weight*set_score + bounty`；
阶段二 `fitness = 增益 − 0.25 × 交互成本`（λ=0.25）也是浮点。
这两者评的是「这个个体 / 教法好不好」，不是判「这道题对不对」。
**别说「全系统无 float」，一翻 `scoring.py` 就打脸。**

**③ SymPy 不进判分链路**
README 里的 **1200 个 SymPy 随机样本**是开发期四族公式交叉验证，
判分链路连 SymPy 都没 import。别说成「用 SymPy 判分」。

**④ 前端还有一套 BigInt 镜像判分**
`web/tutor.html` 用 BigInt 存分子分母 + 自定义 `bgcd()`，
修的是 JS `Number` 超过 2^53 静默失精的问题（答案允许到 64 位）。
与后端是**两套代码、同一口径**，别混说成「复用后端」。

## 8. 答辩三档版本

**15 秒版**
> 「参考答案由本地精确算术算出来，模型连答案都看不到；
> 模型只交一个字符串，过六道闸、三级解析，两边都化成 `Fraction` 比一次。
> 零浮点、零次让模型当裁判，每条对错都能在仓库里重算。」

**45 秒版**：在 15 秒基础上加「四模板 + Bareiss 整数消元」和「三态、格式错也占分母防刷分」。

**被追问版**：直接翻 `app/executor.py` 指 `solver_view()` 白名单、
`judge()` 六道闸、`_ref_fraction()` 的字符串存储，比任何口头解释都硬。
