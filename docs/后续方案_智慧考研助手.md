# 后续方案：从「养蛊机」到「日新」智慧考研助手

> 定位一句话：**养蛊机证明"prompt 可以被演化"，考研助手证明"演化出来的 prompt 能教人"。**
> 前者是方法，后者是产品。评委看不懂演化公式，但看得懂"这个学生三天前错在哪，今天为什么给他这道题"。

本文回答四件事：**做什么、凭什么有效、用多少小时、怎么讲**。

---

## 0. 先纠一个认知：不能直接把冠军 prompt 拿来教人

养蛊机里个体的 fitness 是 **"互出题 + 互解题"的成绩**。这个 fitness 衡量的是"会做题"，不是"会教人"。
直接把冠军 prompt 丢进对话，最可能的表现是：**讲得又长又准，但学生听不懂**——因为它从来没被"学生有没有进步"筛过。

所以真正要做的不是"复用 prompt"，而是**迁移 fitness**：

| | 养蛊机（现在） | 考研助手（下一步） |
|---|---|---|
| 个体是什么 | 3 个基因：`solve_prompt` / `set_prompt` / `self_check` | 4 个基因：+ `teach_prompt`，并加 5 个**策略参数**（讲解粒度、追问次数、例题数、提示梯度、复习系数） |
| fitness 是什么 | 一代 72 个槽位的正确数 | **学生前后测的标准化增益 − 交互成本** |
| 淘汰依据 | 出题区分度 + 解题正确率 | 同样的题库，谁让学生"用更少题达到掌握" |
| 演化对象 | prompt 文本 | **教学策略**（文本 + 参数一起演化） |

这一格变化是整个方案的支点：**基因从"会答题"变成"会教人"，fitness 从"分数"变成"进步量"。** 引擎（`app/run.py` 的代事务、快照、排名、降噪）几乎不用改，只换个体表示和 fitness 函数——这是复用率最高的地方。

## 1. 产品形态：一个学生，四个闭环

```
        ┌──────────── 学生说一句话 / 答一道题 ────────────┐
        ▼                                               │
 ① 记忆层  L1 事件 → L2 会话摘要 → L3 画像（可审计）      │
        ▼                                               │
 ② 学生模型  KC 掌握度（BKT）+ 题目难度（Elo-lite）+ 记忆强度（FSRS）
        ▼                                               │
 ③ 教学决策  选哪个 KC → 出哪道题（难度对齐）→ 用哪级提示
        ▼                                               │
 ④ 判分与归因  精确判分（复用 executor）→ 错因分类 → 更新模型
        └───────────────────────────────────────────────┘
```

四个闭环各自的"日新"落点：

| 闭环 | 日新的具体表现（能演示、能截图） |
|---|---|
| 记忆 | 第 1 天它只知道"你错了"；第 3 天它说"这个点你 11/12 独立做对过 2 次，今天只复查 1 题" |
| 学生模型 | 掌握度曲线不是人填的，是每次答题后按 BKT 更新出来的，可回放每一步 |
| 教学决策 | 同一道题，对 3 个不同水平的学生给出 3 种不同的下一步（不是同一段话换个语气） |
| 策略演化 | 两套教学策略在模拟学生上对打，赢的那套被保留——**"谁教得好"由数据决定，不由作者自称** |

## 2. 架构与模块（贴着现有仓库长，不另起炉灶）

### 2.1 复用清单（这些一行都不用重写）

| 现有资产 | 在新系统里的角色 |
|---|---|
| `app/executor.py` 四族模板 + `judge()` | **判分层**：题目答案精确可复核，不靠 LLM 打分；这是和教育类 App 拉开差距的核心 |
| `prompts/setter.md`、`prompts/solver.md` | 出题/解题基座，教学版在其上加"难度旋钮"与"讲解要求" |
| `app/run.py` + `runtime.py` + `store.py` | **演化引擎**：代事务、不可覆盖快照、独立恢复分支、降噪估计，整条都能用 |
| `app/scoring.py` | `est_score` / `ranking_key` / 同分打散，直接换成教学 fitness |
| `app/ancestor.py` | 分型失败率 → 改成**分 KC 掌握度**，大屏曲线直接复用 |
| `app/export.py` | 白名单导出（不带 reference / holdout），学生端和评委端共用 |
| `data/` 125 题 | 前测 / 后测 / 练习池的底料 |

结论：**新代码集中在 `app/student/` 和 `app/tutor/` 两个包，约 1200–1500 行**，其余是改字段。

### 2.3 关键数据结构（先冻接口，免得三个人各写一套）

**L1 事件**（每答一题一行，append-only，永不修改）

```json
{"t":"2026-11-14T11:20:03+08:00","sid":"stu_01","task_id":"T0412",
 "kc":["integral_definite"],"difficulty":0.62,"correct":false,
 "hint_level":1,"elapsed_s":184,"err":"concept",
 "answer":"1/2","ref_kind":"rational"}
```

**L3 画像**（只存稳定事实，每条带证据与时间）

```json
{"sid":"stu_01","facts":[
  {"k":"目标","v":"数一，2027 届，目标 110+","conf":0.95,
   "src":"evt_0007","t":"2026-11-14"},
  {"k":"薄弱","v":"定积分换元时忘记换上下限","conf":0.8,
   "src":["evt_0031","evt_0044"],"t":"2026-11-14",
   "supersedes":null}
]}
```

> `supersedes` 字段是"日新"的技术表达：**不是覆盖旧记忆，而是记下"哪条新证据推翻了哪条旧判断"**。演示时能展开成一条时间轴，评委一看就知道这不是普通聊天记录。

**教学策略个体**

```json
{"id":"G07_C2","genes":{"solve_prompt":"...","set_prompt":"...",
 "self_check":true,"teach_prompt":"先问学生打算怎么下手，再给最小提示。"},
 "params":{"explain_grain":"step","probe_rounds":2,"example_count":1,
 "hint_ladder":["hint","scaffold","step","answer"],"review_k":0.9}}
```

## 3. 算法：三件小事，别上深度学习

黑客松不需要 DKT。三个能讲清楚、能当场手算的模型就够，而且更抗问。

### 3.1 掌握度：BKT 四参数（每 KC 一组）

四个参数：`p_init`（初始掌握）、`p_transit`（一次练习后学会）、`p_slip`（会却答错）、`p_guess`（不会却蒙对）。

答对后：

```
p_known = p * (1 - slip) / (p * (1 - slip) + (1 - p) * guess)     # 后验
p_new   = p_known + (1 - p_known) * transit
```

答错则把 `1-slip` 换成 `slip`、`guess` 换成 `1-guess`。**30 行代码，纯 stdlib，可手算验证。**

升级规则（防止"讨好型教学"）：**必须"无提示、独立、换一道同 KC 不同参数的题"再对一次**才升一级。学生说"我懂了"不算——这条直接借 Jane Street `socratic-tutor` 的 "levels are earned, not given"。

### 3.2 难度：Elo-lite（每题一个难度值）

```
期望正确率 E = 1 / (1 + 10^((d_item - θ_student)/400))
d_item += K * (实际 - E)        # 算错 → 题目变难；算对 → 题目变易
```

选下一题时挑 `|d_item - (θ + 0.1)|` 最小的题——**略高于当前水平**（"i+1"），不是最难的题。这条能被评委追问："为什么不做最难的？" 答：**学习发生在最近发展区，不是挫败区。**

### 3.3 记忆：mini-SM2 + 可选 py-fsrs

每个 KC 一张"卡"，答对间隔 ×1.7、答错重置。三行公式，够演示"三天后它主动来找你复习"。

如果要更硬：`pip install fsrs`（`open-spaced-repetition/py-fsrs`，MIT，**纯离线、可 JSON 序列化**）。接口设计成可替换，答辩时说"我们内置简化版，正式版可无缝换 FSRS"——比强行接一个重依赖更稳。

### 3.4 fitness：怎么把"教得好"变成一个数

```
gain      = (post - pre) / (1 - pre)          # Hake 标准化增益，0..1
cost      = 0.3 * 题量/基准 + 0.7 * 提示次数/基准
fitness   = gain - 0.25 * cost
```

**为什么要减 cost**：只加增益的话，演化会选出"无限提示、把答案嚼碎"的策略——增益高，但学生没学会。减掉成本，才能演化出"话少而准"的策略。这一条是设计上的"防作弊"，答辩值得单说。

## 4. 比赛日程：三档，按剩余时间挑

### A 档｜12 小时（只做能演示的最小闭环）

| 时间 | 做什么 | 交付 |
|---|---|---|
| 0–2h | `kc.py` 标 2 个 KC（定积分、行列式）+ `bkt.py` + `difficulty.py` | 掌握度能更新，单测 10 条 |
| 2–5h | `hint.py` + `dialog.py`：提示梯度 + 一次一问 | 命令行能跑一段真实对话 |
| 5–7h | `memory.py` + `profile.py`：L1 落盘、L3 画像带证据 | "三天前你错过这题"能复现 |
| 7–10h | `tutor.html` 学生端单页（复用现有 `web/` 样式与 `serve.py`） | 断网可演示 |
| 10–12h | 5 分钟演示脚本 + 一页"为什么判分可信" | 彩排两遍 |

> A 档**不做策略演化**，只讲"我们下一步要演化策略"。诚实，但少了最亮的点。

### B 档｜24 小时（推荐，含策略演化）

在 A 档基础上加：

| 时间 | 做什么 |
|---|---|
| 12–16h | 扩到 6 个 KC：新增 4 族模板（导数极值、极限、数项级数、矩阵幂/秩），每族 20 行 + 20 条测试 |
| 16–20h | `sim_student.py` 三档模拟学生 + `fitness.py`，用现有 `run.py` 跑 3 代 × 6 个体 |
| 20–23h | 大屏加一页"策略演化"：两套策略的 gain-cost 散点 + 胜者基因 diff |
| 23–24h | 评测报告 + 答辩稿 |

### C 档｜48 小时（如果有两天）

再加：真人 n=1 案例（自己或同学跑 30 题，前测后测）、校准图（预测正确率 vs 实际，Brier score）、留出题迁移测试（在没见过的 KC 上测）。

**建议选 B 档。** A 档缺"日新"的实证，C 档容易被"样本太小"问穿；B 档刚好有"演化出策略 + 3 代对照数据"，可讲且可验。

## 5. 怎么证明它有效（评委只信这个）

四组对照，全部离线可复现，用固定种子：

| 对照 | 自变量 | 看什么指标 |
|---|---|---|
| ① 难度自适应 vs 固定难度 | 选题策略 | 达到同一掌握度所需题量（越少越好） |
| ② 梯度提示 vs 直接给答案 | 提示策略 | 后测独立正确率（给答案的会后测暴跌） |
| ③ 有记忆 vs 无记忆 | 上下文 | 同一学生第 3 次会话的首题命中率 |
| ④ 演化策略 vs 手工策略 | 策略来源 | `gain - 0.25cost` |

**必须同时报的三个诚实数字**：

1. **n = 3 个模拟学生 × 每人 30 题**——样本小，写清楚，不吹显著性；
2. **模拟学生有偏**：它的"会忘"是按我们的假设写的，所以它只能证明"策略在模型内更优"，不能证明"真人一定更优"；
3. **题域窄**：只做可精确判分的题型（高数 + 线代），不做概率论证明题、不做英语作文。**这是设计选择，不是能力缺陷。**

> 答辩时这句话最值钱：**"我们不在做不了的题上装能做，我们只在能复核的题上给结论。"**

## 6. 演示脚本（5 分钟，按这个顺序排）

1. **0:00–0:40｜问题**：考研数学最大的浪费不是不会，是"不知道自己哪里不会"，于是反复刷已经会的题。
2. **0:40–1:40｜它先问你三道题**（诊断）：屏幕上是三道不同 KC 的题，答完立刻出现 6 个 KC 的掌握度条（有两条明显低）。
3. **1:40–2:40｜下一题是算出来的**：点开"为什么给我这道题" → 弹出三行：该 KC 掌握度 0.31、题目难度 0.35、上次同类错因"换元忘换限"。**这一步是全场的核心，一定要点开。**
4. **2:40–3:30｜答错不直接讲**：系统只收窄提问（"你换元以后，上下限变成什么了？"），学生自己发现矛盾；第二次还错才给脚手架。
5. **3:30–4:10｜时间旅行**：把系统时间往后拨三天（或回放已录日志），它主动推一道复习题，并说"你 11/12 独立做对过 2 次，这次只复查 1 题"。
6. **4:10–4:50｜策略是演化出来的**：一页散点图，两套教学策略的 gain-cost，赢的那套基因 diff 高亮；一句话——"这套教法不是我们写的，是从 6 套里选出来的。"
7. **4:50–5:00｜收尾**：判分可复核、记忆可审计、范围诚实。

## 7. 评委大概率会问的八个问题

| 问题 | 怎么答（一句一答，别背稿） |
|---|---|
| 和教育类 App 有什么不同？ | 三件事：判分不用 LLM（可复核）、教学策略是演化出来的（有对照数据）、记忆带证据链（能说出为什么给你这道题）。 |
| 你的 prompt 凭什么比人写的好？ | 不比"好"，比"可验证"：同一批模拟学生、同一套题、同一个种子，跑出来 gain 更高才留下。 |
| 模拟学生不是真人，结论有意义吗？ | 只能证明"策略在模型内更优"，真人只做了 n=1 案例。我们把这句话写在报告第一页，不藏在附录。 |
| 题目是不是提前背过答案？ | 每题都有 `reference`，但**只有服务端持有**；学生端收到的只有 `type / statement / answer_format` 三个字段（这条已经在现有系统里用测试锁住了）。 |
| 会不会让学生变懒？ | 升级必须"无提示独立做对两次"；直接给答案的策略在 fitness 里被成本项惩罚掉了。 |
| 数据隐私？ | 全本地 JSON/SQLite，不联网也能演示；画像可一键导出与删除。 |
| 只能做数学？ | 只做"答案能精确复核"的题型。英语作文、政治大题我们不做——因为没法验证，做了就是骗人。 |
| 下一步是什么？ | 把 KC 从 6 个扩到考研数学一全纲，接入真实学生 30 人做 A/B。 |

## 9. 风险与止损

| 风险 | 触发信号 | 止损动作 |
|---|---|---|
| 时间不够做演化 | 距截止 < 12h | 掉到 A 档，只讲"下一步"，不伪造数据 |
| 模拟学生太像"送分童子" | 所有策略 gain 都 > 0.8 | 加"会忘 + 会蒙"两种噪声，重跑；仍失真就只报相对排序，不报绝对值 |
| 新增模板族出 bug | 交叉验证不一致 | 每族先过 `tools/sympy_crosscheck.py`，不过就不进题池 |
| 演示机型断网 | 现场网络 | 全部本地：静态页 + JSON 数据 + `app/serve.py`，不依赖任何云服务 |
| 被问"这是不是 GPT 套壳" | 评委第一问 | 打开 `judge()` 现场改一个数字，判分立刻从 right 变 wrong——**"我们的对错不经过模型"** |

## 10. 与现有仓库的对接顺序（建议照这个来）

1. 先把 `config` 的硬限额补齐、跑通 pilot（这一步与本文无关，但是所有演示的地基）；
2. `kc.py` 标注 125 题 → 这是唯一需要"人工判断"的活，越早开始越好；
3. `bkt.py` + `difficulty.py` + 单测（半天）；
4. `dialog.py` 最小闭环（命令行），先不接页面；
5. 页面 + 演示脚本；
6. 演化 + 对照实验（放最后，因为它依赖前面全部跑通）。

> **不要先做页面。** 页面最容易给人"快完成了"的错觉，而它恰恰是最不能证明任何事的部分。
