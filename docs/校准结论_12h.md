# 校准结论（12 小时版）

> 跑于 2026-11-14 12:35–12:50，真模型（`deepseek-chat`，服务端恒回显 `deepseek-flash`）。
> 命令：`python -m app.run --config config.local.json --calibrate runs/calibration.json`
> 样本：6 seeds × 20 题 × 3 次 = **360 次调用**，耗时约 50 秒。

---

## 1. 结果

| 配置 | 通过率 | 规格区间 20%–80% | 未判定 |
|---|---|---|---|
| `solver_temperature = 0.7`（协议值） | **12.8%**（46/360） | ✗ 低于下限 | 0 |
| `solver_temperature = 0.2` | **11.9%**（43/360） | ✗ 低于下限 | 0 |

**降低温度没有收益**（12.8% → 11.9%，差异在噪声内）。已回滚到协议值 0.7，不做"偷偷调参"。

## 2. 按模板拆开看，问题非常集中

| 模板 | 0.7 时 | 0.2 时 | 判断 |
|---|---|---|---|
| `det`（行列式，3–5 阶） | **0/180 = 0%** | 0/180 = 0% | 完全不会 |
| `gaussian_odd` | 3/54 = 5.6% | 0/54 = 0% | 几乎不会 |
| `gamma`（n 到 9） | 18/54 = 33.3% | 18/54 = 33.3% | 会算但常错 |
| `poly` | 25/72 = 34.7% | 25/72 = 34.7% | 会算但常错 |

20 道题里只有 **1 道**三次全对，**6 道**三次全错。

**格式零失败**：360 条回答全部是合法字面量（`-60`、`-63/31250`…），`unanswered` 为 0。
所以这不是解析问题，是**算错**。

## 3. 但简单题它能做对

另外抽了 7 道简单题直接问（同样是 `solver.md` 的提示词、温度 0.7）：

| 题 | 参考 | 模型 | 判定 |
|---|---|---|---|
| 2 阶行列式 `[[2,1],[1,3]]` | 5 | `5` | ✅ |
| 2 阶行列式 `[[-4,7],[5,-2]]` | -27 | `-27` | ✅ |
| 3 阶行列式（行和为常数） | 0 | `0` | ✅ |
| 3 阶行列式 `[[2,-1,0],[3,5,1],[-2,4,6]]` | 72 | `80` | ✗ |
| 多项式定积分 `[3,-2,1]` on `[-1,2]` | 9 | `9` | ✅ |
| Γ 积分 `c=1,n=4,r=2` | 3/4 | `3/2` | ✗（差 2 倍） |
| 高斯奇次矩 `c=2,k=1,r=3` | 1/9 | `1/9` | ✅ |

**5/7 正确（71%）**。

## 4. 结论

> **不是"模型不会数学"，是"校准题对它太难，而且它没有草稿纸"。**

三条证据：
1. 题目越简单越准（2 阶全对，3 阶开始错，4–5 阶全崩）；
2. 参数越大越准不了（`n=9` 的 Γ 积分要算 `9!` 与 `r^{10}`，`gaussian` 要记 `k!/(2r^{k+1})`）；
3. 温度不是杠杆（0.7 与 0.2 几乎一样），说明不是抽样波动，是**能力边界**。

`det` 的 0/180 尤其说明问题：校准卷里 10 道 det 全是 **3–5 阶**，而模型在 2 阶上 100%、3 阶上 50%。

## 5. 三条可选修法（按代价排序）

| 修法 | 代价 | 预计效果 | 需要谁同意 |
|---|---|---|---|
| **① 难度分档**：校准/共同卷混入 T1（2 阶 det、`n≤3` 积分） | 改 `data/`（C 的数据） | 通过率大概率进 30–50% | C |
| **② 给草稿纸**：允许 solver 先写算式再给 `{"value":...}` | 改 `prompts/solver.md` + 同步规格 §3（当前 `tests/test_prompts.py` 断言逐字一致会红） | Γ 类"差 2 倍"这类错会明显减少 | A+B+C |
| **③ 换模型**：官方直连或更强模型（当前中转恒回显 `deepseek-flash`） | 换 key | 未知，取决于目标模型 | 徐潇 |

**今天不建议动 ②**：它会同时改提示词基线与校准基准，12 小时内返工风险高。① 最便宜，但今天下午 C 在忙前端。

## 6. 对今天的影响：几乎没有

- **助教演示不依赖 solve 准确率**：学生答题、判分、掌握度、提示全在本地引擎里，模型只负责出题和讲解；
- **养蛊机的 fitness 会偏低**：如果晚上要展示"演化出更好的 prompt"，现在这个 12.8% 会让曲线难看。**建议今晚不展示演化曲线，改讲"我们已经能测量能力上限，且知道它卡在哪两类题上"**——这句话配上本文第 2 节的表，比一条漂亮的假曲线上可信。
