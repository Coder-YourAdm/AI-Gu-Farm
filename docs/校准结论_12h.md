# 校准结论（12 小时版）

> 跑于 2026-11-14 12:35–13:00，真模型（`deepseek-chat`，服务端恒回显 `deepseek-flash`）。
> 样本：6 seeds × 20 题 × 3 次 = **360 次调用**，每档约 50 秒。

---

## 1. 结论先行：难度是唯一杠杆

| 档 | 定义 | 通过率 | 是否在 20–80% |
|---|---|---|---|
| **原卷** | det 3–5 阶，积分 n 到 9 | **12.8%**（46/360） | ✗ 太低 |
| **mix** | 只把 10 道行列式降到 2–3 阶，10 道积分原样 | **52.8%**（190/360） | ✅ |
| **t1** | 全简单（2–3 阶 det、n/k≤2、r≤3） | **92.8%**（334/360） | ✗ 太高 |

> **"稍微提高一点"的最简单方法：把行列式从 3–5 阶降到 2–3 阶，其余不动。**
> 12.8% → 52.8%，正好落进预设区间。三档数字同时证明：这不是模型坏了，是原校准卷难度失衡。

## 2. 证据链

### 2.1 原卷 12.8% 的拆解

| 模板 | 通过率 | 说明 |
|---|---|---|
| `det`（3–5 阶） | **0/180 = 0%** | 完全不会 |
| `gaussian_odd` | 5.6% | 几乎不会 |
| `gamma`（n 到 9） | 33.3% | 会算常错 |
| `poly` | 34.7% | 会算常错 |

360 条回答**零格式错误**（`unanswered=0`），所以是算错，不是解析坏。

### 2.2 简单题它能做对（抽 7 题直接问）

2 阶 det 2/2、3 阶 det 1/2、poly ✅、gamma ✗（差 2 倍）、gaussian ✅ → **5/7 = 71%**。

### 2.3 温度不是杠杆

`solver_temperature` 0.7 → 12.8%，0.2 → 11.9%，差异在噪声内。已回滚到协议值 0.7。

## 3. 用什么方法落的 52.8%

新增 `tools/make_tier_dataset.py`，用**同一套 `executor` 生成器**造题，签名/题面/参考值全部由
`normalize_task` 计算，不手写答案：

```bash
python tools/make_tier_dataset.py --tier mix --out data_t2    # 只降 det 难度
python tools/make_tier_dataset.py --tier t1  --out data_t1    # 全简单
python -m app.run --config config.local.json --calibrate runs/calibration_t2.json --data-dir data_t2
```

`tests/test_make_tier_dataset.py` 锁了两条：题集合法且签名互斥；**mix 的积分与底卷逐字节一致**（只改 det）。

## 4. 对今天的影响

- **助教演示不依赖 solve 准确率**：判分、掌握度、提示全在本地引擎，模型只出题讲解。
- **给评委的分档校准表（§1）比一条曲线值钱**：它证明"我们知道能力边界在哪、会自己校正难度"。
- 演示题池直接用 `mix`/`t1`：学生能答对，掌握度曲线才有起伏，演示才好看。
