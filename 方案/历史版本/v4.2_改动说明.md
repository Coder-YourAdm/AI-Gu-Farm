## 1 C1 · p 的分母不是 5，是 n_t

### 旧

```python
p = 答对数 / 5
```

### 新

```python
n_t = len(task.answers)          # 逐题记录
p   = task.correct_count / n_t
band = (1/n_t, 1 - 1/n_t)        # n_t=5 时正好是原来的 [0.2, 0.8]
counted = n_t >= 4               # n_t < 4 不计入区分度统计
```

### 为什么

v4.1 的 6.8 写了"每人固定答 M−1 道；自己那道被作废时随机再跳一道"。这条规则解决了**得分分母**不一致，但制造了一个新洞：**通过率的分母不再恒为 5**。

6 人各出 1 题、P6 的题被作废 → M=5 → P6 只能随机跳过别人的一道 → 那道题只有 4 人作答。代码如果还除 5：

- 实际 4 人答、2 人对（真 p=0.50），被算成 `2/5 = 0.40`
- 当代通过率被记低 0.1 → **难度虚高一档**
- 出题分从应有的 1.00 掉到 0.80 → **出题人白丢分**

**偏向是系统性的**：作废越多 → 少人答的题越多 → 难度全线虚高。而作废多的代恰好是 M 小的代，**会在难度线上造出假跳变**，事后和真的加载-卸载混在一起分不清。

## 2 C2 · 出题分：从"及格就满分"改成连续分 + 3 代均值

### 旧

```python
set_score = 1 if 0.2 <= p <= 0.8 else 0      # 二值
total = solve_score + set_score              # 出题端最多 1 分，解题端 0–5
```

### 新

```python
set_score_now = max(0.0, 1 - 2*abs(p - 0.5))       # 0..1 连续
set_score_hist.append(set_score_now)                # 沿血脉继承，留最近 3 代
total = solve_score + 2.0 * mean(set_score_hist)    # 出题端 0..2
```

| p | 旧 | 新 |
|---|---|---|
| 0.5 | 1 | **1.00** |
| 0.4 / 0.6 | 1 | **0.80** |
| 0.2 / 0.8 | 1 | **0.40** |
| 0 / 1 | 0 | **0.00** |

### 为什么

1. **分辨率只有一档**：每人每代只出 1 题，出题分只能是 0 或 1，占总分 1/6。自然选择几乎全压在解题上，**出题端的进化压力非常弱**。
2. **更糟的是它会变成常数**：第 3–5 代六个个体都能拿到那 1 分（只要不出极端题），出题分就成了**常数**。常数不产生任何选择压力，出题端从此停止进化。
3. **但曲线还在涨**（解题那头在涨），**你完全看不出出题端已经停了**。而"互相出题互相解"恰好是对外宣传的主卖点——**设计与宣发不一致，且不会报错**。

改成连续分之后，从"4 对 1 错"精调到"3 对 2 错"分数会从 0.80 涨到 1.00，**它才有理由继续调**。而它努力的方向正是"卡在会与不会之间"——这条窄带就是整套系统最值钱的产出。

### 为什么还要 3 代平均（这一步不能省）

`p` 是从 `n_t≈5` 个样本估出来的。n=5 时 p=0.4 的 95% 区间约 **[0.12, 0.77]**，p=0.6 是 **[0.23, 0.88]**，两者高度重叠。

**所以：把二值改成六档，如果不做平均，只是把随机数变成了小数点后的随机数。** 个体这代得 0.8 分，可能只是那 3 个人恰好会做。

3 代平均让有效样本从 1 题变 3 题，**不增加一次调用、不增加一秒钟**——这是唯一免费的降噪手段。代价是选择压力滞后 1–2 代，20 代的规模能接受。

### 血脉继承规则（必须写死，否则实现会各写各的）

| 子代来源 | `set_score_hist` |
|---|---|
| 精英 | 原样继承自己 |
| 交叉 | 两父代历史逐代平均，长度取短的那个 |
| 变异 | 继承母本 |

- 长度上限 3，超出丢最老的；不足 3 条时用已有条数平均
- 出题被作废 → 当代记 0（重出机会已用掉）
- 基准线题不参与任何人的出题分
- **`set_score_hist` 不进 genotype JSON**，否则交叉算手会去改它

## 3 C3 · 断崖 → 两次加载-卸载（固定第 8、15 代）

### 旧

```python
if gen > 5 and 祖先尺难度 连续 4 代未升档 and gen - last_inject >= 4:
    注入 1 道基准线题
```

### 新

```python
INJECT_GENS = {8, 15}          # 固定，无条件
```

### 为什么（两条，第一条是它自相矛盾）

1. **"用停滞触发高潮"本身就是矛盾**：难度一路升 → 条件不满足 → 断崖不来；断崖来了 → 说明前面已经停了 4 代，等于**拿故障当卖点**。
2. **"连续 4 代不升档"太严**：难度每 2–3 代升一档时，永远凑不满 4 代连续不动。v4.1 里这个高潮实际上**大概率不发生**，而它被写成"唯一高潮画面"。

### 为什么固定注入反而更强

| | 自适应断崖 | 两次加载-卸载 |
|---|---|---|
| 诚信 | 触发自发、题目外生，被问一句就问穿 | **主动说是实验设计** |
| 一定发生 | 条件可能恒假 | **一定发生，能排练** |
| 能测出什么 | 一次"撞墙了" | **两次恢复速度的对比** |

**真正的证据不是"撞墙"，是恢复变快。** 第一次 5 代才爬回，第二次只要 2 代——这是整套系统里最直接的一句"它比之前强了"，**比难度曲线还硬**，因为两次注入的是同类同档的题，排除了"题目变简单"的干扰。

这也解决了答辩里最难受的那个问题（"这不就是你设计好的？"）。标准答案：**"对，加载-卸载本来就是设计出来的。设计的是压力，不是结果——5 代 vs 2 代这个差别不是我们写出来的。"**

### 配套约束

- 两次注入**必须同类型同档**（都是 L5 反常积分或 5×5 行列式），否则恢复代数不可比
- 恢复代数定义：粗线难度回到注入前水平所需的最少代数（容差 0.05，8 代内没回记 ">8"）
- **基准线题计入祖先尺，但不计入当代通过率、出题分、平均区分度**（否则每代都被它拖到底）

### 落地

- §8 整节重写（8.1 加载-卸载 / 8.2 准入 / 8.3 处理）
- §4 参数表：加载-卸载循环、基准线题两行
- §9 大屏：注入竖虚线 ×2 + 直接写恢复代数
- §12 展板与 90 秒稿、§12.7 舞台脚本 5:00–8:00 段
- §15 答辩口径：新增 2 条（"那不算零干预吗""出题端后来还在变好吗"）

## 4 C4 · 撤掉进程池，改成入口限复杂度

### 旧

```python
with ProcessPoolExecutor(max_workers=4) as ex:
    ans = ex.submit(solve_task, task).result(timeout=5)
```

### 新

| 层 | 做法 |
|---|---|
| 入口 | `AST ≤ 30` + 幂限制（指数必须数值常量且 `|e| ≤ 10`，底数不许是幂）+ 表达式 ≤ 200 字符 |
| 求解 | `mpmath.quad(..., maxdegree=6, limit=100)` |
| 出口 | 只告警：记录最慢 3 题；单代墙钟 > 120s 标记异常 |

### 为什么

**Windows 是 spawn 模式**：每次 `submit` 要重启解释器并重新 `import sympy`（0.5–1.5s）。一代约 20 次 submit，**光启动就 10–30 秒**，"30 秒/代"直接翻倍，而且这个开销随并发数线性增长。

更根本的理由：**单进程里的 Python 无法安全中断正在执行的 C 级运算**。`thread` 杀不掉、Windows 没有 `SIGALRM`。与其写一个假的超时，不如**保证输入根本进不了慢路径**。

满足 `AST ≤ 30` 的式子，单进程 `mpmath.quad` 通常 < 100ms。

### 风险与兜底

入口限制是"白名单"式的，理论上仍可能有漏网的慢结构。兜底是**离线记录最慢 3 题的结构**，把该结构加进黑名单模板——用 3 代时间收敛，而不是在现场等超时。

### 落地

- §7.3 新增 AST 与幂限制
- §7.4 整节重写，明确"不设单题超时"及原因
- §16 失败模式矩阵：「一代太慢」处置改为查 AST 上限

## 5 C5 · 祖先尺是锯齿，不是阶梯

**3 个祖先 × M 题 ≈ 15 个二值判定**，分辨率 1/15，均值噪声约 **±0.13**。真实难度 0.53 的某一代，可能画出 0.40 或 0.66。

- 每条难度线画两条：**细实线**（原始值，诚实）+ **粗实线**（3 代滑动平均）
- **判"升档"一律用粗线**，不许拿单代波动当故障或当进步
- 排练时看到 ±0.13 的抖动是正常的，别去改机制

落地：§4.2.1、§9 大屏图元、§16 失败模式新增「把锯齿当故障」一行。

## 6 C6 · 祖先的选择方向原来反了

### 旧

"第 0 代总分最高 / 中位 / 最低各一"

### 新

**按留出卷得分从高到低取 3 个，并校准平均留出卷通过率到 60%–75%。**

| 3 个祖先平均通过率 | 含义 | 处置 |
|---|---|---|
| 60%–75% | 正常 | 冻结开跑 |
| < 60% | 尺子几代内饱和 | 换更强模型档，或降留出卷难度 |
| > 85% | 起点贴 0，前 3–4 代看不出变化 | 提高留出卷难度 |

### 为什么

难度 = `1 − 祖先通过率`。**祖先越强，起点难度越低，剩下可上升的空间越大。**

- 祖先通过率 35% → 起点难度 0.65，只剩 0.35 空间，**第 8 代左右就饱和**，后 12 代全贴在 1.0
- 祖先通过率 70% → 起点难度 0.30，还有 0.70 空间，够跑完 20 代

用留出卷得分而不是总分：第 0 代还没有出题分，总分≈解题分；留出卷是纯外部度量。

落地：§4 参数表、§4.2.3 整节新增、§13 D0 检查表第 3 项。

## 7 C7 · 六人极差手测提前到赛前数天

### 旧

放在 D0（赛前最后一晚），10 分钟。

### 新

**提前数天，2 小时手测**：5 道题 × 6 种方法论不同的 prompt，固定温度 0.7。

### 为什么

**这是全案唯一一个单点故障**：如果六份 prompt 得分挤在一起，淘汰就是抽签，整个进化不成立。而 D0 只有一晚，pilot 失败就来不及换任务域。

极差 < 15 个百分点 → **先别写任何代码**，回去重做六份流派（分类先行 / 换元优先 / 数值验证 / 逆向构造 / 极简分步 / 自我复核）。

落地：§13 排期表新增「赛前（提前数天）」行 + 手测方法小节 + D0 检查表第 0 项。

## 8 C8 · 驳回：「6 人 × 20 题 = 120 个样本」

外部建议提出用 120 算标准误，可把 ±11% 压到 ±4.5%。**不采纳。**

这是**伪重复（pseudoreplication）**：

- 同一道题由 6 个人回答，这 6 个答案高度相关（同题、同模型、同批 prompt 家族）
- 要推广的对象是"这个模型在这类题上的能力"，**抽样单位是题目（20），不是答题记录（120）**
- 用 120 会虚假抬高自由度，答辩被懂统计的评委问一句"你的独立样本是什么"就穿

**维持 20 题、±11%、只说方向、永不说"显著"。**

不过有一个可以放心说得更硬的指标：**两次恢复代数（5 代 vs 2 代）不是统计量，是直接观测**，不需要抽样推断。

落地：§14 统计口径新增驳回说明 + 「排序说明」小节。

## 11 明确不采纳（避免重复讨论）

| 建议 | 理由 |
|---|---|
| 用 120 个答题记录算标准误 | 伪重复，见 §8 |
| 祖先调到 30%–40% 通过率 | 方向反了：通过率越低，尺子上升空间越小，第 8 代就饱和 |
| 保留自适应断崖 + 只在第 12 代兜底 | 条件可能恒假，且"用故障触发高潮"说不圆 |
| 每人每代出 2 道题（直接扩样本） | 一代调用 54 → 108，时间翻倍。先用免费的 3 代平均，跑通有余力再考虑 |

## 12 三个需要盯的风险

1. **3 代滑动让选择压力滞后 1–2 代。** 运气好的个体会多活一两代。20 代规模可接受，但如果第 5–8 代看到"明显该淘汰的没被淘汰"，不要急着改公式——先看 3 代后是否自然修正。
2. **连续分在 n=5 时仍然是噪声。** 3 代平均只是摊薄，不是消除。所以**出题分只用于排序，不用于对外报数字**；对外只报"出题分从 X 涨到 Y"这种粗粒度趋势。
3. **两次注入必须真的同档。** 如果第二次不小心用了更简单的题，恢复更快就不说明任何事。**注入前用 3 个祖先各测一遍，p 必须都是 0**，并且把两次题目一起写进证据包。
