## 一 · 积分 7 条

### I1 `poly` coeffs=[1,1], l=0, u=1

被积函数 `x + 1`，原函数 `x²/2 + x`。

```
[x²/2 + x]₀¹ = (1/2 + 1) − 0 = 3/2
```

期望 `3/2` · 三路径一致 ✅

### I2 `poly` coeffs=[3,−2,1], l=−1, u=2

被积函数 `3 − 2x + x²`（coeffs 按升幂），原函数 `3x − x² + x³/3`。

```
F(2)  = 6 − 4 + 8/3  = 2 + 8/3  = 14/3
F(−1) = −3 − 1 − 1/3 = −13/3
F(2) − F(−1) = 14/3 + 13/3 = 27/3 = 9
```

期望 `9`（分母为 1，按整数编码）· 三路径一致 ✅

> ⚠️ 区间跨 0，是专门用来抓符号处理的。实现里若把 `F(l)` 的符号写反，会得 `1/3` 或 `−1/3`。

### I3 `poly` coeffs=[0,0,5], l=1, u=2

被积函数 `5x²`，原函数 `5x³/3`。

```
[5x³/3]₁² = 5(8 − 1)/3 = 35/3
```

期望 `35/3` · 分子分母互素，不可再约 ✅

### I4 `gamma` n=1, rate=2, c=1

`∫₀^∞ c·xⁿ·e^{−r·x} dx = c·n!/r^{n+1}`

```
1 · 1! / 2² = 1/4
```

期望 `1/4` ✅ · 题面中指数为 1 时不写上标（`x e^{-2x}` 而非 `x¹`）

### I5 `gamma` n=9, rate=8, c=5 —— **分母上限用例**

```
5 · 9! / 8¹⁰ = 5 × 362880 / 1073741824
            = 1814400 / 1073741824
1814400 = 2⁷ × 14175     （14175 = 3⁴·5²·7 = 81·25·7）
8¹⁰     = 2³⁰
约分 → 14175 / 2²³ = 14175 / 8388608
```

期望 `14175/8388608` ✅

> ⚠️ 这条最容易出事的地方：**值相等但分母没约分**。`1814400/1073741824` 和
> `14175/8388608` 数值相同，但分母位数不同。规格 §2.4 的位数上限是按**最简形式**判的，
> 不约分会被判成超限。测试里要断言的是 `Fraction(14175, 8388608)`，不是数值近似。

### I6 `gaussian_odd` k=0, rate=2, c=3

`∫₀^∞ c·x^{2k+1}·e^{−r·x²} dx = c·k! / (2·r^{k+1})`

```
3 · 0! / (2 · 2¹) = 3/4
```

期望 `3/4` ✅ · `k=0` 时指数为 1，题面写 `x` 不写 `x¹`

### I7 `gaussian_odd` k=5, rate=1, c=−2 —— **负系数不丢符号**

```
−2 · 5! / (2 · 1⁶) = −2 × 120 / 2 = −120
```

期望 `−120` ✅

> ⚠️ 丢符号会得 `+120`。这是唯一一条负期望值的积分用例，符号处理错了别处看不出来。

### I8 拒绝组（6 个输入，全部 `(False, 原因)`）

| 输入 | 为什么必须拒 |
|---|---|
| `rate = 0` | 分母为 0，闭式解退化 |
| `n = 0` | gamma 型 n 从 1 起；n=0 会让 `x⁰` 与模板定义冲突 |
| `c = 0` | 零被积函数，积分恒 0，题目无意义且答案可猜 |
| `template = "eigen"` | 非法模板名，不在三族白名单 |
| `coeffs = [1, 0]` | 末项为 0 → 实际降次，与声明的次数不符，签名会撞 |
| `upper = lower` | 零宽区间，积分恒 0，无区分度 |

**A 要确认的**：这 6 条返回的是「拒绝」，不是「抛出异常」，也不是「静默修正参数」。

## 二 · 行列式 7 条

### D1 `[[2,1],[1,3]]`

`2·3 − 1·1 = 5` ✅ 2 阶基础。

### D2 `[[1,2,3],[4,5,6],[7,8,10]]` —— 3 阶含负结果

```
1·(5·10 − 6·8) − 2·(4·10 − 6·7) + 3·(4·8 − 5·7)
= 1·(50−48) − 2·(40−42) + 3·(32−35)
= 2 + 4 − 9
= −3
```

期望 `−3` ✅ · 覆盖「结果可为负」

### D3 `[[1,2],[2,4]]` —— **奇异矩阵**

`1·4 − 2·2 = 0`

期望 `0` ✅

> ⚠️ 这是 Bareiss 主元全零的分支。实现若用「主元为 0 就换行」而没有「整列全零就返回 0」
> 的判断，会死循环或 ZeroDivisionError。**这条不是算数值，是测分支不炸。**

### D4 `[[2,1,0],[1,3,1],[0,1,2]]`

```
2·(3·2 − 1·1) − 1·(1·2 − 1·0) + 0·(1·1 − 3·0)
= 2·5 − 1·2 + 0
= 8
```

期望 `8` ✅

### D5 `[[3,1,2],[0,−2,5],[0,0,7]]` —— 上三角

行列式 = 对角积 = `3 × (−2) × 7 = −42`

期望 `−42` ✅ · 覆盖「上三角 + 含负数」

### D6 `[[0,1],[1,0]]` —— **首元素为 0，必须换行**

`0·0 − 1·1 = −1`

期望 `−1` ✅

> ⚠️ 换行一次符号翻一次。忘了翻会得 `+1`。

### D7 `[[0,2,1],[3,0,1],[4,5,0]]` —— **零主元 + 多轮换行**

```
0·(0·0 − 1·5) − 2·(3·0 − 1·4) + 1·(3·5 − 0·4)
= 0 − 2·(−4) + 15
= 8 + 15
= 23
```

期望 `23` ✅

> ⚠️ D6/D7 是同一类风险的两档：D6 换一次行，D7 需要多轮。符号翻错两次会「负负得正」，
> 表面上 D7 过了、D6 挂了——所以两条都要有。

### D8 拒绝组（4 个输入，全部拒绝）

| 输入 | 为什么必须拒 |
|---|---|
| `[[1,2,3],[4,5,6]]` | 非方阵，行列式无定义 |
| 元素 `2.0` | float 输入 → 精度不可控，规格禁止 float |
| 元素 `true` | Python 里 `True == 1`，不显式拒会被静默当成 1 |
| `[[5]]` | 1 阶，规格最小阶为 2 |

**A 要确认的**：`true` 这条尤其容易漏——`isinstance(True, int)` 在 Python 里是 `True`，
不写 `type(x) is not int` 就拦不住。

## 三 · S1–S8：待 A 交 `test_contracts.py` 后核

C 不手算这 8 条（它们不是数值），只核「断言写法是否真能拒绝」。核对时我会问每条一句：
**「它在拒绝什么？把这条断言删掉，什么错误会被放过？」**

| # | 场景 | C 会核的点 |
|---|---|---|
| S1 | 响应 9000 字符 > `max_response_chars=8000` | 是否**解析前**就拒；要用 mock 计数确认 `json.loads` 调用次数为 0 |
| S2 | `sqrt(4)` / `1; import os` / `1/0` | 三条都必须是 `unanswered`，**不是 `wrong`**，且不抛异常 |
| S3 | `NaN` / `Infinity` / `1e31` / 65 位整数 | 指数上限 30、位数上限 64 是否真生效；`1e30` 应通过，`1e31` 应拒 |
| S4 | 同签名提交两次 | 第二次返回 `duplicate`，`dedup_set` 大小不增（**断言大小，别只断言返回值**） |
| S5 | 同 coeffs 不同区间 | 两个签名不同、都入池 → 证明区间进了签名 |
| S6 | `solver_view` 键集合 | 恰为 `{type, statement, answer_format}`；再断言序列化结果**不含参考值数字串** |
| S7 | 出题失败、`refetch_rounds=2` 用尽 | `slots_created == 0` **且 `solver_calls == 0`**（后者更有说服力） |
| S8 | `Fraction(35,3)` 与 RNG state 往返 | `Fraction` 往返相等；RNG 连抽 100 数与原文逐位相同 |

**S7 是最容易写错的一条**：三个轮次、每人最多 2 次尝试、共 6 次机会，但**一次 solver 都不能发**。
只断言状态是 aborted 不够，要断言 `solver_calls == 0`——否则「发了 solver 才算失败」这件事没被测到。
