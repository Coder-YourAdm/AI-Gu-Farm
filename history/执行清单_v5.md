## 1 需要你们提供的东西

### 1.1 模型与账号（阻塞项，今天就要）

| 事项 | 具体要求 | 为什么卡在这 |
|---|---|---|
| 模型选型 | provider、`base_url`、精确 `model` id | 全程冻结同一个模型，中途换模型全部结果作废 |
| API key | 放环境变量，**不进仓库** | 快照和日志都要过滤密钥 |
| 预算上限 | 一个具体金额或 token 数 | 决定能否跑满 E/F 各 3 趟（13563 次调用） |
| 速率限制 | 每分钟请求数、并发上限 | 决定 42 小时能不能排下 6 趟 |

v5 只给了调用次数，没给价格，因为单价随模型和时段变。**你们给预算，我算配置**：钱少就减少重复趟数或代数（按 §13 的降级顺序），钱够就跑满。

### 1.2 组织方规则（赛前必须问到）

这几条直接改变配置，问清楚再动手：

- 赛前能否写代码、能否调用模型 API（v5 §13 明确写「以组织方规则为准」，现在是空的）
- 正式演示时长、提交格式（代码仓库链接 / 现场演示 / 提交材料）
- 组织方是否提供 API 额度或指定模型
- 场地条件：网络是否稳定、有无独立电源、投影分辨率

如果「赛前不能调模型」，pilot 只能压到比赛早期，那么 00–06H 那段必须先把判分做完，一点不能拖。

### 1.3 人力分工

## 2 要做的事

### 阶段 0 · 赛前准备（允许就现在做）

- [ ] **0.1 环境**：Python 3.11+ 已满足（本机 3.13.14 / 3.14.3 都有），需装 `httpx`、`pytest`、`pytest-asyncio`。当前三项均未安装。
- [ ] **0.2 `executor.py` + 24 个用例**：按附录 A 逐条抄参数与手算期望，写测试时直接写字面量，禁止先跑 `solve()` 再回填。
- [ ] **0.3 `datasets.py`**：四类题集（calibration / common_dev / challenge_pool / holdout）、结构化签名、`manifest.json` 的 SHA-256。
- [ ] **0.4 `prompts/` 五个文件**：`setter.md`、`solver.md`、`crossover.md`、`mutate.md`、`seed_genotypes.json`。六份初代基因在施工图 §3.5 有全文，直接抄，不要现编。
- [ ] **0.5 dry-run 预算脚本**：按生效配置算调用数，能输出「无重试理论值」和「含 refetch 预留」两栏。

做完这五条，判分和题集就齐了，后面现场只需接模型。

### 阶段 1 · 00–06H 判分成立

- [ ] `pytest` 24 条全绿
- [ ] 题面生成 4 条示例字符串**逐字相等**（`statement()` 必须是纯函数，不带模板名和变量名）
- [ ] 数据集分区不串：题集签名互斥，含挑战池全部 5 道
- [ ] 非法输入在求值前被拒（布尔值、非整数、超范围）

**验收**：判分无分歧，任何人手算能复核。

### 阶段 2 · 06–12H 打通模型与策略

- [ ] `llm.py`：全局限流、角色 token 预算、原始响应记录、网络重试 2 次
- [ ] calibration 跑通：6 策略 × 20 题 × 3 次
- [ ] 出 **pilot 第一数**：平均通过率是否落在 20%–80%

**决策点**：一片全对 → 模板太好识别，启用施工图附录 B 的线性组合变体后重测；一片全错 → 换参数范围或换模型。不要靠加代数硬撑。

### 阶段 3 · 12–18H 一代跑通

- [ ] `orchestrator.py` 完整代事务，78 次调用结构（6 出题 + 30 互答 + 24 共同卷 + 18 祖先）
- [ ] `scoring.py`：同题公平（作业题难度不影响 `solve`）、同分用本地 RNG 打散
- [ ] 三个算子：精英克隆、交叉 2、变异 1（`gene_key` 变化即从零起算）
- [ ] `store.py`：原子快照 + RNG state 序列化
- [ ] `challenge.py`：第 8、15 代注入，达标/退役/censored 三态

**验收**：一代 M=6，槽位 30/24/18 稳定，公平性反例通过。

### 阶段 4 · 18–22H pilot 5 代 + 锁协议

跑 5 代，**必须产出三个数，缺一个不能锁**：

- [ ] 格式失败率与 `refetch_round` 分布（5 代里有 2 代要整代重做 = 机制不够，先修）
- [ ] `fitness_window=1` vs `=2` 的排名翻转率 → 决定正式用哪个
- [ ] 实测代耗时与单次调用 token → 替掉预算里所有口头估计

- [ ] 锁 `config.json`、锁数据集、算 `manifest` 签名

锁定后不许改语义字段。改了就是新实验，要标来源。

### 阶段 5 · 22–30H 正式运行

- [ ] E 组 3 趟（完整演化）
- [ ] F 组 3 趟（冻结对照），与 E 配对
- [ ] 失败趟如实记录，**不重跑到好看的那趟**
- [ ] 运行结束统一跑留出评测（5 个检查点 × 6 人 × 20 题 = 600 次/趟）

**时间不够时的降级顺序**（v5 §13 规定，不许跳着砍）：

动画与血脉连线 → A 消融 → 第二次挑战 → live 代数 → 总代数

**不砍**：精确执行器、同题解题分、E/F 对照、留出隔离、日志。

### 阶段 6 · 30–36H 证据与物料

- [ ] 证据包：运行清单、留出表、逐题答案、配置与数据签名、失败记录
- [ ] 大屏 `index.html`：祖先分层失败率原始线 + 三代均线，挑战专图，血脉卡
- [ ] 90 秒录屏（数字由实际运行填入）
- [ ] A1 展板：机制四步、E/F 结果表、挑战各自结果、证据二维码。**不印未测数字**

### 阶段 7 · 36–42H 排练

- [ ] 展位彩排：断网状态能完整播放
- [ ] 舞台稿：结果与限制前置 → 现场短段（1–3 代）→ 录屏 → 计分与执行器 → E/F 对照 → 用途
- [ ] 备机验证：代码、数据、录屏在另一台机器同样能跑

## 4 最低交付线

做到以下五条就算完整交付，**即使结果是没有改善**：

1. 程序能跑通一代
2. 评分可解释、可手算复核
3. E/F 有成对的可追溯记录
4. 留出卷独立、未参与选择
5. 观众能用自己的话复述这个项目在测什么

结论写「未观察到可靠改善」也是合格交付；编造上升曲线才是失败。
