## 现象

`方案/技术规格_v5.md` §2.1 规定 det 的矩阵元素范围是 `[-9, 9]`，但附录 A 的 D2 用例本身越界：

| 位置 | 内容 |
|---|---|
| 规格 L626 | `D2 | [[1,2,3],[4,5,6],[7,8,10]]` → `-3` |
| 规格 §2.1 | 矩阵元素 ∈ `[-9, 9]` |

元素 `10` 超出上界 1。

## 为什么 36 条测试全绿也没发现

`tests/test_executor.py:100` 的辅助函数直接调 `solve_exact()`：

```python
def _det(m):
    return solve_exact({"template": "det", "params": {"matrix": m}})
```

`test_D2` 走 `_det()`，**跳过了 `validate_task()`**。所以这条用例测的是 Bareiss 的算术（`-3` 算对了），测不到「这道题能不能进入流水线」。

**这不是代码错。** `bareiss()` 本来就该能算任意整数矩阵，用越界输入测它反而更彻底。问题只在于：这条用例不能当作「合法出题」的样本。

## 30 秒复现

```bash
python -c "from app.executor import validate_task; print(validate_task({'template':'det','params':{'matrix':[[1,2,3],[4,5,6],[7,8,10]]}}))"
# -> (False, '矩阵元素 10 超出 [-9, 9]')
```

## 影响范围（都不阻塞）

- 我这边 `data/verify_bank.json` 的 V07 抄的就是这条 D2，已被 `tests/test_contract_compat.py` 拦下，现标注为「测纯函数可用、测全流程须跳过」
- 125 道正式题集不受影响：全部通过你的边界预检

## 建议（选一个，成本都很低）

1. **保留 D2 当 bareiss 单测**，注释写明「越界输入，仅测算术，不用于出题流程」——我倾向这个，改动最小且不丢覆盖面
2. 换一个合法矩阵，期望值同步改。注意不能简单把 10 改成 9：`det([[1,2,3],[4,5,6],[7,8,9]]) = 0`，矩阵奇异，会撞上「非奇异」要求
3. 在附录 A 加一行注：D2 为算术用例，不代表合法参数域

不建议动 §2.1 的 `[-9,9]`：这个边界是为了控制题面字符数与难度，改它会牵连 `solver_view` 的题面长度和 125 题的重签。

## 为什么用这个顺序反馈

| 做法 | 问题 |
|---|---|
| 微信上直接说「你有个盲点」 | 他会先防御，先争论「10 也能算啊」，浪费一轮 |
| 只说结论不给复现 | 他要花 5 分钟自己验，赛制下他不会验，事情就没了 |
| 先定责再提方案 | 这条**根本不是他的错**，是规格前后矛盾。定错责，后面的建议他也听不进去 |

所以顺序是：**先给 30 秒复现 → 明确说不是代码错 → 只让他做一个选择题**。
对方要做的决策越少，改动落地越快。
